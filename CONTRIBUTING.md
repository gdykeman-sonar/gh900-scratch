# Contributing to gh900-scratch

Thanks for taking the time to contribute. This repository holds study notes and small working examples for the GitHub Foundations material. Fixes, clarifications and additions are all welcome.

## Before you start

- Search the existing [issues](https://github.com/gdykeman/gh900-scratch/issues) and [pull requests](https://github.com/gdykeman/gh900-scratch/pulls) to avoid duplicating work.
- For anything larger than a typo, open an issue first so the change can be discussed before you write it.
- Report security problems privately. See [SECURITY.md](SECURITY.md).

## Making a change

1. Fork the repository, or create a branch if you have write access.
2. Create a branch from `main` with a short, descriptive name, for example `fix-typo-in-notes` or `add-community-files`.
3. Make your change. Keep each pull request focused on one topic.
4. Commit with a clear message. Use the imperative mood and keep the first line under 72 characters, for example `Add notes on branch protection`.
5. Push the branch and open a pull request against `main`.
6. Fill in the pull request template and link the issue it resolves with a closing keyword, for example `Closes #2`.

## Review

- Code owners are requested for review automatically on every pull request. They are listed in [.github/CODEOWNERS](.github/CODEOWNERS).
- Respond to review comments by pushing further commits to the same branch.
- Once approved, the pull request is merged with a merge commit and the branch is deleted.

## Style

- Write in Markdown. Use one `#` heading per file and sentence case for headings.
- Wrap code, commands and file names in backticks, and use fenced code blocks for multi-line examples.
- Prefer short paragraphs and lists over long blocks of text.
- Link to the official GitHub documentation when you state a behavior.

## Reporting bugs and requesting changes

Use the issue templates. A good report states what you expected, what happened instead, and the steps to reproduce it.

## Conduct

Be respectful and constructive in issues, pull requests and reviews. Harassment and personal attacks are not acceptable, and maintainers may remove comments or block contributors who engage in them.
